# 吉客云 CK031 库存分析

本目录为库存分析网页：官方库存 API → 按条码批次采集与核验 → 按货品编码汇总 → 历史快照、Excel 导出、钉钉机器人预警。
完整业务要求以根目录“项目需求文档.md”为准。第一期只接库存；在途、均值、周转与补货列保留为空。

## 配置与使用

1. 将 .dev.vars.example 复制为 .dev.vars，本地填写吉客云 AppSecret；已存在的配置不要覆盖。AppKey 为 92058521，固定仓库 CK031。
2. 依赖已安装后用 `npm run dev` 启动，使用终端打印的 localhost 地址。本地登录由 Sites 开发预览提供。
3. 打开“采集范围”，从 Excel 复制该仓库完整的 skuBarcode 列，每行一个。货品编码仅在与规格条码相同时可用。修改范围后预警关闭，核对后重新开启。
4. 点击“采集库存”。每批 500 个条码，每页 200 条，查到末页并逐项核对后发布。清单外记录、未返回条码、分页失败或数量冲突会报告错误并保留上次成功数据。
5. 点击“导出 Excel”导出当前成功快照的全部货品，搜索筛选不截断导出；A–H 沿用模板业务列，I 为单位，另有“采集说明”页。原模板保留。

仅按仓库编码查询已证实会漏货品。全仓覆盖取决于条码清单完整性；未返回条码不填 0。

## 钉钉配置

四项填写在本地 .dev.vars；云端使用同名服务端运行变量，本地配置不随源码上传。

- DINGTALK_CLIENT_ID：应用“凭证与基础信息”的 Client ID（原 AppKey），不是 App ID。
- DINGTALK_CLIENT_SECRET：同页面完整 Client Secret，不能使用掩码值。
- DINGTALK_ROBOT_CODE：应用“机器人”配置中的 Robot Code。
- DINGTALK_OPEN_CONVERSATION_ID：机器人已加入的目标企业内部群 ID，不是 CorpId 或 AgentId。

启用企业内机器人发送消息权限并发布应用版本；机器人须加入目标企业内部群。无需工作台页面或 H5 免登。
群 ID 可用根目录 tools/dingtalk-group-id.mjs 获取，操作见 tools/钉钉群ID获取说明.md。工具用 Node.js 24，仅接收回调并确认协议，不发群消息。

预警默认关闭。网页开启后，每次成功采集检查阈值并汇总发送；相同范围、阈值和低库存内容不重复通知。发送不确定时不自动重发，以群内结果为准。当前没有定时采集任务。

## 数据与开发

React / Vinext 网页，Cloudflare Workers 服务端，D1 / Drizzle 保存范围、快照、采集记录及预警设置。网站默认私有，登录由托管平台提供；本地 mock 仅用于 loopback 开发，不进入生产输出。

日期列为相同清单的每日最后一次成功库存快照，缺失显示“—”。库存变化不当作销量。数量和长 ID 精度保留；同编码名称或单位冲突阻止合并。Excel 超出 15 位有效数字时数量存文本。

- `node tests/run.mjs`：库存完整性、7001 条码分批及机器人模拟请求验证，不发真实消息。
- `python tests/check-xlsx.py`：独立校验生成的样本 Excel。
- `npm run db:generate`：schema 修改后生成 SQL 迁移；迁移放在 drizzle/，运行时不建表。
- .sites-runtime/、.wrangler/、.dev.vars、.env 和本地工具状态不提交。

发布沿用 Sites 托管流程，运行配置在服务端保存。全仓对账、真实机器人消息验证及第二期入库接入仍分别需要相应业务配置和数据。
