# 吉客云 CK031 库存分析

本目录为多仓库库存与销售分析网页：仓库编码 → `erp.stockquantity.get` 自动取得 SKU → `erp-stock.stock.skulist` 查询可购数量 → 按货品编码汇总 → 每日销售库存差额、Excel 导出、钉钉预警。
完整业务要求以根目录“项目需求文档.md”为准。第一期只接库存；入库在途按后续阶段推进。运行与迁移详见 [运行与迁移说明](docs/运行与迁移说明.md)。

## Ubuntu 迁移版本（当前）

本版本使用 Next.js Node 服务、SQLite、独立账号与后台 worker，正式部署按 [Ubuntu部署操作手册](docs/Ubuntu部署操作手册.md) 操作。Docker 仅绑定 127.0.0.1:3108；历史 Site 数据需要单独迁移。以下旧版说明保留作业务背景，不再作为当前启动命令。

## 原 Site 版本配置与使用（历史）

1. 将 .dev.vars.example 复制为 .dev.vars，本地填写吉客云 AppSecret；已存在的配置不要覆盖。AppKey 为 92058521，默认仓库 CK031；网页可按编码新增和切换仓库。
2. 依赖已安装后用 `npm run dev` 启动，使用终端打印的 localhost 地址。本地登录由 Sites 开发预览提供。
3. 选择仓库，或点击“增加仓库”填入吉客云编码。无需设置采集范围；名称会在第一次成功采集后同步。
4. 点击“采集库存”。自动获取全量 SKU；条码查询参数每批不超过1000字符，每页200条，查到末页并逐项核对后发布。缺失规格、分页失败或数量冲突会报告错误并保留上次成功数据。网页每页默认100条，可选200/500/1000。
5. 点击“导出 Excel”导出当前成功快照的全部货品，搜索筛选不截断导出；A–H 沿用模板业务列，I 为单位，另有“采集说明”页。原模板保留。

`erp-stock.stock.skulist` 仅按仓库查询会漏货品；现在用 `erp.stockquantity.get` 先生成全仓条码清单，再查询可购数量。两接口权限均须开通，未返回的规格不填0。

## 钉钉配置

四项填写在本地 .dev.vars；云端使用同名服务端运行变量，本地配置不随源码上传。

- DINGTALK_CLIENT_ID：应用“凭证与基础信息”的 Client ID（原 AppKey），不是 App ID。
- DINGTALK_CLIENT_SECRET：同页面完整 Client Secret，不能使用掩码值。
- DINGTALK_ROBOT_CODE：应用“机器人”配置中的 Robot Code。
- DINGTALK_OPEN_CONVERSATION_ID：机器人已加入的目标企业内部群 ID，不是 CorpId 或 AgentId。

启用企业内机器人发送消息权限并发布应用版本；机器人须加入目标企业内部群。无需工作台页面或 H5 免登。
群 ID 可用根目录 tools/dingtalk-group-id.mjs 获取，操作见 tools/钉钉群ID获取说明.md。工具用 Node.js 24，仅接收回调并确认协议，不发群消息。

预警默认关闭。网页开启后，每次成功采集检查阈值并汇总发送；相同范围、阈值和低库存内容不重复通知。发送不确定时不自动重发，以群内结果为准。当前没有定时采集任务。

## 数据与开发

原 Site 版本：React / Vinext 网页，Cloudflare Workers 服务端，D1 / Drizzle 保存仓库、快照、每日基准、采集记录及预警设置。网站默认私有，登录由托管平台提供；本地 mock 仅用于 loopback 开发，不进入生产输出。

日期列为昨天基准库存减今天基准库存所得的销售库存差额，仅显示已有可计算的相邻日期；缺日不跨天，新增规格或单位变化不填0，保留负值。每日08:00后首次成功采集为固定基准，手动刷新只更新当前库存。旧的部分样本不纳入全仓销售计算。数量和长ID精度保留；Excel超过15位有效数字时存文本。

仓库默认采集时间为北京时间08:00。当前Site仅用于功能测试，真实云端定时任务尚未启用；迁移到用户自己的服务器和域名后启用。认证后台入口及服务器触发脚本已准备，不依赖网页常开。密钥只存服务端环境。

- `node tests/run.mjs`：库存完整性、7001 条码分批及机器人模拟请求验证，不发真实消息。
- `python tests/check-xlsx.py`：独立校验生成的样本 Excel。
- `npm run db:generate`：schema 修改后生成 SQL 迁移；迁移放在 drizzle/，运行时不建表。
- .sites-runtime/、.wrangler/、.dev.vars、.env 和本地工具状态不提交。

发布沿用 Sites 托管流程，运行配置在服务端保存。全仓对账、真实机器人消息验证及第二期入库接入仍分别需要相应业务配置和数据。
