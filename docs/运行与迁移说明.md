# 库存与销售分析运行说明

## 当前功能

仓库编码 → `erp.stockquantity.get` 全量分页取得仓库 SKU → 自动分批调用 `erp-stock.stock.skulist` → 核对仓库、规格、条码、单位后，汇总 `orderAbleQuantity` 为当前库存。每次采集重新获取 SKU，无需手工维护范围。参数 `skuBarcode` 每批最长 1000 字符，官方网关每页 200 条；终页和全部规格均通过核验才发布。超过官方 10000 条目录分页窗口时明确失败，需要补充游标查询，不发布截断清单。

仓库名称从第一次成功采集自动同步。各仓库的当前库存、日基准、采集记录与导出独立；新增仓库保存默认时间 `08:00`、时区 `Asia/Shanghai`。

每天北京时间08:00后第一份完整成功快照是当日固定基准；再次手动采集只更新当前库存。销售日期 D 的数值 = D 的基准库存 − D+1 的基准库存。只比较相邻日期和相同单位，不用缺失的 SKU 填零，不跨过缺日，不截断补货导致的负数。它是库存差额，不能等同于销售订单成交数量。采集分多个实时请求完成，更新时间为整次采集完成时间，接口不提供全仓原子快照。

以前的少量条码及12条样本保留，但标记为 `legacy-partial`，不混入本次 `auto:v1` 全仓基准与销售表。页面只显示已有可计算日期。每页默认/最少100，可选200、500、1000；库存排序在服务端对全部符合条件的记录排序后分页。

## Site 测试阶段

目前**尚未启用每天08:00的自动任务**，也未创建本机任务。前端、手动完整采集及受认证保护的后台入口可用于功能验证。每日基准使用测试阶段第一次成功采集的真实时间，未伪造08:00时间。Site仍保持原有私有访问范围。

`POST /api/scheduled-sync` 无需浏览器登录，通过服务器环境中的 `INVENTORY_CRON_SECRET` 认证。私有Site访问还需平台服务令牌，传入 `OAI-Sites-Authorization`。密钥只放服务端环境，不放浏览器、源代码、域名URL或任务文本。入口从数据库读取已登记仓库与所属用户，不接受调用方指定用户。只处理08:00后尚无基准的仓库，同一仓库并发受锁保护；已完成返回 `already_complete`，失败仓库保留以前的完整库存，其他仓库继续处理。

`GET /api/scheduled-sync` 使用同样认证，读取快照及采集记录以确认后台写入。目录/库存请求失败不生成假数据；首次后台执行前须已有仓库登记。

## 迁移到自己的云服务器与域名

当前运行时为Cloudflare Worker/D1与Sites登录，不能只复制静态网页到普通服务器。迁移时须一起处理：后端运行时、数据库及数据迁移、替代Sites登录、服务端吉客云配置、HTTPS与真实云端定时任务。用独立服务器访问控制替换Sites身份，保持各账户/仓库隔离。数据库迁移必须包括 `warehouses`、`sync_runs`、`stock_snapshots`、`stock_entries`、`daily_slots` 和 `alert_settings`；历史快照及每日基准都要迁移。

部署迁移适配后的后台并配置环境变量：`JACKYUN_APP_KEY`、`JACKYUN_APP_SECRET`、`INVENTORY_CRON_SECRET`、`INVENTORY_SITE_URL`。钉钉配置在需要启用预警时另行设置，默认不开启。不要导出或展示真实密钥。

服务器使用系统定时器/cron每天北京时间08:00执行 `node scripts/daily-sync.mjs`。系统定时器设置 `Asia/Shanghai`；若只支持UTC，时间为每日00:00 UTC。迁移前保存仓库默认时间属于配置，并不意味着任务已启用；完成真实定时器登记和一次无人打开网页的写入/读回验证后，才将界面状态改成已启用。

`daily-sync.mjs` 从环境读取凭证；调用同一后台入口，失败返回非零退出码，服务器定时器可告警/重试。重复触发不会覆盖当日基准。正式上线时保留真实测试快照及实际采集时间；不要将下午测试快照改成08:00快照。需要严格24小时口径时，可将测试期基准独立归档，从正式定时首日重新开始该口径。

上线验收：浏览器关闭时仍产生快照；全部仓库分别完成或留下明确失败记录；同日重跑跳过已完成；连续两日形成前一日销售列；Excel当前库存与网页一致；升级数据库不丢原有记录。
