# 金蝶存销雏形使用说明

更新日期：2026年10月20日。

金蝶入口提供报表上传、明细预览、仓库分组、规则重算、批次切换和Excel导出。按原Excel“明细”复现A—CN共92列、列宽、底色、宋体、黑色网格、冻结前6列及首行，移除卡片式指标区。历史年月、门店差异、价格缺口和新商品分类继续暂缓，不阻止预览。

“明细”中A—F优先保留旧主档原值（包括字面0和空白）；G—CC保留原表历史缓存值，不推断年份。CD—CN按本批来源计算，日期相关表头改标“本批”，避免将本批数据冒充10月1—8日或10月9日旧数据。“原表对照”独立展示原92列表头及缓存值；两个视图均可导出，原件不改写、不执行原表公式。

## 暂缓的事项

用户明确暂不处理门店销量差115及退货规则、历史月份年份及统一库存时点、未匹配价格及单位有效期、新商品四维映射及POD空白含义。

这些事项不阻碍本阶段导入与预览。销量保留源数量正负号，不按赠品标记筛选公司出库；公司销量沿用六项客户排除。历史月份不补造，不把整月销量写进旧10月1—8日列。分类缺失、缺价及来源未覆盖显示为空，不按0替代。金额只在该商品库存和价格都有值时计算，作为参考，不声明为完整财务库存金额。

旧明细可补充主档和四维资料。新商品没有已维护的四维资料时仍保留，不从名称猜分类，不自动填“其他”或“非POD”。

## 使用步骤

1. 共用公司钉钉登录后选择“金蝶”，不另设金蝶账号密码。默认本地预览同样显示钉钉入口且关闭密码登录；未配置公司应用及HTTPS回调时会明确提示，不能用本机回归账号代替真实钉钉身份。
2. 点击“准备数据”，进入“准备数据→核对来源→生成明细”三步窗口。“星空采集＋星辰上传”展示后续混合路径；接口尚未联调，本轮不请求ERP、不显示虚假连接或采集成功。星空配置可临时填写，关闭配置窗口立即清空密码，不写本地存储、不提交服务器；测试连接、开始采集暂不开放。
3. 当前可选“全部上传Excel”走完流程：分别选择星空销售出库汇总、星空物料收发汇总、星辰销售明细、星辰库存查询和销售价目表。旧明细可选。每一项也可明确选择本账户成功批次中的已保存版本；“沿用当前批次来源”一次带入，之后可只替换某一份文件。
4. “核对来源”逐项显示文件名、状态、来源批次时间、行数和原导出条件。新文件标注“已选文件，待提交核验”，不伪装成已上传或已采集；选定的文件只在当前页面保留，刷新页面需重选。已保存版本明确提示“沿用原件，不会重新采集”。暂缓的时点与口径问题继续保留说明。
5. 到“生成明细”检查五项必需来源。未准备、接口待联调、文件格式或大小不符合要求时列出具体原因并禁用生成按钮。实际生成时才上传新文件、拷贝选定旧原件、校验SHA256、逐表核验表头与合计并计算。成功后显示完成结果，可查看明细或导出；失败保留选择和旧成功报表，不发布为空结果。复用与上传在同一来源互斥，不重复叠加。
6. 搜索物料编码或名称；可筛选本批缺价、价格冲突和四维资料待补。列头下拉支持整张表的内容筛选和升降序；清除后恢复原表行顺序，新商品追加在末尾。单击单元格查看地址及完整值，方向键移动；点击编码或双击单元格查看源文件及源行。冻结前6列和首行，支持横向滚动、75%—125%缩放以及历史/本批快速定位。
7. 调整仓库分组后重算；从“数据批次”选择旧版，查看当时的数据和规则。
8. 点击“导出Excel”，导出当前工作表视图的完整数据，不因搜索、筛选或分页截断。导出92列并附“仓库范围”“来源与说明”，保留模板配色、列宽和冻结；复用来源记录原批次ID。原表对照仅含原表40,578个商品；本批明细保留43,927个并集商品。92列布局已复现，不代表所有历史统计口径均已重新核验。

单份文件不超过32MB，本批上传与复用的原件合计不超过50MB；支持不含宏的xlsx。格式、合计或文件损坏时显示失败原因，并保留上次成功结果。复用版本在服务器核验账户归属、成功状态、来源类型及原件哈希，不能引用其他账户的文件。生产反向代理需允许至少50MB上传，导入请求超时需覆盖解析时间。

## 数据与存储边界

共用身份认证，金蝶业务保存在独立的`kingdee.sqlite`及`kingdee-files`中。默认位于现有`INVENTORY_DB_PATH`同目录，因此服务器已有storage挂载可持久保存；也可分别设置`KINGDEE_DB_PATH`、`KINGDEE_STORAGE_DIR`。金蝶库路径不能与吉客云库存库相同。

所有批次、商品、原件和导出均按账户归属验证。金蝶导入和重算不写入吉客云仓库、快照或任务表。网页每个账户的仓库设置保存在金蝶库；`data/kingdee-default-rules.json`只是新账户默认模板，不会在部署时覆盖已维护设置。离线工具继续使用`金蝶存销分析/config/rules.json`，二者当前预置名单一致，网页后续修改不回写离线文件。

当前采用独立解析线程，单次解析限制180秒和768MB旧生代堆，尚未建设独立常驻服务或自动定时采集。新报表发布使用数据库事务；原始文件不放入public或源码镜像。

## 本地运行与回归

在`web-app`目录执行：

```powershell
npm run test:kingdee
npm run build
npm run preview:platforms
```

默认本机入口为`http://127.0.0.1:3108`，仅公司钉钉登录，密码入口关闭。使用`.sites-runtime/platform-preview/company`独立数据库。真实扫码要求配置`DINGTALK_CORP_ID`、登录应用Client ID/Secret、管理员身份和`INVENTORY_SITE_URL`的HTTPS站点，并在钉钉登记该域名的回调。配置缺失时显示未就绪；不自动读取示例密钥或改用密码。

开发回归才显式运行`npm run preview:platforms:test`，使用127.0.0.1:3109及`.sites-runtime/platform-preview/current`隔离测试库，终端生成测试账号密码。与默认钉钉预览分开，不代表已完成真实OAuth回调。另一个终端运行`node scripts/load-kingdee-preview.mjs`可把已留存六表导入该测试账户并校验导出；脚本拒绝默认公司预览和生产地址。两个预览均重启保留导入。Windows上先关闭本次预览进程再重新构建，避免运行包锁定。

HTTP回归：`node tests/kingdee-http.mjs`。真实源表解析回归：`node tests/kingdee-real-files.mjs`；独立历史缓存逐格比较：`python tests/check-kingdee-template.py`；真实导出逐格比较：`python tests/check-kingdee-export.py`。后三项仅在本地存在已留存资料及真实测试结果时运行。普通生产代码不包含这些业务源文件。
