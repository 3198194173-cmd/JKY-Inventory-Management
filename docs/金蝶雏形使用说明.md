# 金蝶存销明细使用说明

更新：2026-10-23。当前方向是继承原Excel“明细”，在原行中追加统计，不另建一张业务编码并集表。

## 原明细与新数据

底表为 `casebang 存销明细 2026.10.09.xlsx` 的“明细”页，共40,578个不重复物料编码、92列。原文件不修改，不将业务原件放入public或源码镜像。

1. 首次进入“准备数据”，在“原明细底表”选择原Excel，点击“仅载入原明细，不追加采集列”。此时保留A—CN原表数据、行号和格式，不要求先有五份业务/价格表。
2. 后续选择已保存底表，并准备公司销量、公司库存、门店销量、门店库存、结算价五项来源。接口采集或Excel均可；吉客云货品属性可选。填写销量起止日期及库存列标注日期，核对原始来源日期后生成。
3. 原编码保持原行号与原名称，A—CJ（含原10.1—8销量及10.9结存）保留。新编码按首次出现的批次追加末尾；下批未出现也不删除，四维可以留空。价格表和货品目录仅补字段，不单独增加明细行。
4. CJ之后、原结算价之前插入七列。例如：10.1-31公司销量、10.1-31门店销量、10.1-31销量、10.23内仓结存、10.23外仓结存、10.23公司结存、10.23门店结存。第一次追加后为99列，原价格/金额四列顺延至CR—CU。
5. 相同销量起止日期＋库存标注日期：更新末尾七列，发布新的可回溯批次；日期不同：保留上期七列，继续向右追加。中间已存在期间不允许重复插入，需选择对应旧批次重算。分组重算沿用该批日期，不额外添列。
6. 原表对照保留原92列布局和历史价格；C列统一为停止采购，使用本批吉客云来源，其余列保留原缓存值。旧批次不会被新生成改写。选择新底表单独载入可建立另一条继承链，不能将不同原件混入同一继承链。

日期是列标题及版本标识，不会修改文件或接口条件。星空昨日、星辰今日的数据仍各自汇总；来源面板保留真实条件，不能声称为同一原子库存快照。

## 公式与缺失数据

原表CK“结算价”是数值，没有该列公式。原CL=`CI*CK`，CM=`CJ*CK`，CN=`CL+CM`；本批价格来源为销售价目表，不能使用库存参考价代替。未匹配或候选冲突价格留空，不按0计价，原价格仍可在原表对照查看。

新列依照原表加法/乘法关系：总销量＝公司销量＋门店销量；公司结存＝内仓＋外仓；公司金额＝公司结存×结算价；门店金额＝门店结存×结算价；总金额＝两项金额相加。完整来源未出现该编码时，单独数量保留空白，空白数量在公式中按0参与计算。缺价时三项金额留空。新公式同时写入Excel，并保留与网页一致的计算缓存。历史原列保留缓存值，不重执行原表旧公式。

公司销量保留赠品和负数，执行已有六项客户排除条件。公司库存精确排除 `123456`、`1234560`、`2020040101`，不影响它们的销量；仅在库存来源出现的这类编码不新增物料行。不自动扩大为所有数字编码；新增排除须明确维护。

## 仓库、样式与分页

仓库分组按账户维护，可增删、调整内仓/外仓/排除。现有默认名单为1内仓、9外仓，以已保存配置为准。名单外仓库不计公司结存；原来源合计仍完整保留用于核验，排除数量另留说明。

保留原表列宽、单元格字体/配色、黑色网格、前6列及首行冻结。新七列沿用原CD—CJ对应行的样式。新增统计不会把旧黄色销量列或蓝色结存列移作其他用途。每页可选100/500/1,000行；筛选和排序针对整张表；导出不受分页或筛选影响。新编码缺少的旧历史保持空白。

## 身份与持久化

公司钉钉统一登录后选择金蝶；共用身份认证，金蝶业务使用独立的 `kingdee.sqlite` 与 `kingdee-files`，不写吉客云库存表。所有源件、批次、继承版本、导出按账户检查，复用原件核验SHA256。每份xlsx≤32MB，上传与复用原件合计≤50MB；Nginx需允许该请求大小。

解析使用独立线程（180秒、768MB旧生代堆）；成功结果通过事务发布，失败保留上次成功版本。服务器已有storage持久化挂载需要保留。部署不会自动带上本机Excel，生产第一次仍需上传底表；无需重新手填分类。

## 验证记录

原明细40,578行×92列，共3,733,176个缓存值及源样式索引独立核对一致。

使用用户提供的10月22日星空来源、10月23日星辰两表及10月19日价格表，继承后44,287行（40,578原行＋3,709新编码），99列。公司销量155,251，门店销量3,838，公司结存217,750，门店结存66,660；这些数值属于所选不同时间来源，不宣称统一时点。

10月19日对照文件独立核验：指定编码6行，纳入内仓的排除量1,147,265；公司结存由1,369,275调整为222,010，公司销量131,412不变。排除后的业务/底表集合为43,925个物料。此旧数据口径与最新来源分开记录。

测试涵盖仅载入底表、原行/原值保留、跨期追加、同期间重算、历史筛选、精确库存排除但保留销量、缺价、公式缓存、账号隔离及失败保留。全部项目lint仍有旧模块的既存错误，本次修改文件的定向lint通过。

### 2026-10-23：停止采购与统一在线采集

所有批次、底表、原表对照及Excel导出的C列统一为“停止采购”，按吉客云 `erp.storage.goodslist` 的 `goodsNo` 精确关联物料编码，以本批来源的 `isStopPurchasing` 显示“是／否”。未返回、未知值或同编码多规格状态冲突均留空，不由旧POD反推。原始上传文件保持不变，但网页和生成的导出不展示旧POD。货品目录仅补属性，不增加明细商品总数；旧批次需采用新货品来源生成新批次后才有该属性。

“准备数据→统一采集在线来源”可选择公司销量、公司库存、结算价、停止采购。后台按所选顺序执行，各模块独立保存原始分页、来源及采集记录。金蝶只登录一次，密码不落盘；后台接管会话，每模块最多45分钟。关闭窗口后继续执行，停止按钮中断当前请求且不启动后续模块；服务重启后未完成任务标记中断。部分失败保留已完成来源，只有完整成功模块可采用。此功能是一次启动后的自动串行流程，尚非定时无人值守采集。

吉客云使用服务端 `JACKYUN_APP_KEY` / `JACKYUN_APP_SECRET`，需要同一应用已订阅货品接口。以 `maxSkuId` 游标分页，核验规格内码去重、游标递增和首批总数，读取空尾页后才发布；处理上限149,999规格。不采用货品来源时停止采购留空；采用来源后显示是/否，未知或冲突仍留空。

价目表最新采集条件：组织103 CASEBANG事业部、编号XSJMB1110，状态／整单状态／失效均为全部（替代早先“失效＝否”截图）。使用只读 `BillQuery`，FormId为 `BD_SAL_PriceList`，每页最多2,000条。用户真实验证了 `FNumber,FMaterialId.FNumber,FMaterialId.FName,FPrice` 四字段及编号过滤的首批2,000行；完整采集所需的组织、分录内码、单位、日期、状态等字段仍未完成真实核验。当前没有配置时明确失败并提示暂用Excel，不将首批样本发布为完整结算价来源。

完整字段由服务端 `KINGDEE_PRICE_SCHEMA` JSON配置，结构为 `fields` 和 `values`。`fields` 必须包含 id、entryId、number、organizationCode、organizationName、materialCode、materialName、price、currency、taxIncluded、priceObject、documentStatus、disabled、unit、effectiveDate、expiryDate，每个值是该账套实际字段标识；其中编码／名称需要选择对应引用属性。`values` 包含 taxIncluded、byMaterial、approved、disabledNo，记录接口真实枚举值以转为导入表头所用中文。不得用单元测试模拟字段配置生产环境。Web API“填写测试数据→生成过滤条件”仅生成FilterString，并不会生成返回字段FieldKeys。

完整价目表保留全部状态分录；生成结算价时现有规则中的人民币、含税、按物料、已审核、CASEBANG事业部限定仍生效，采集范围与价格采用范围分开记录。同编码价格、价目表编号、单位、有效期或失效状态不一致时留空待核验，不任取第一行，不推断有效期。全量查询依靠内码稳定排序、空尾页和重复分录检测，分页不是原子快照。

本次新增回归入口：`npm run test:goods-price`，覆盖停止采购真假与未知、所有视图停止采购一致性、商品集合不扩张、价格条件与精度、统一流程、取消、部分失败及不完整分页拒绝发布。模拟测试不等同于真实ERP全量联调通过。

```powershell

npm.cmd run test:collections

npm.cmd run test:xingkong

```

`node tests/kingdee-http.mjs` 验证隔离HTTP流程；`node tests/kingdee-real-files.mjs` 与 `python tests/check-kingdee-template.py` 核对10月19日原件及原明细缓存。数据结果写入.gitignore忽略的本地验证目录。
