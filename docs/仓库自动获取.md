# 仓库自动获取与初始化

已根据 2026-10-19 查询到的[吉客云官方 API 文档](https://open.jackyun.com/developer/refactored/apidocinfo.html)接入“仓储类 → 仓库 → 开放平台仓库查询”。

- 方法：`erp.warehouse.get`，版本 `v1.0`。
- 网关：`https://open.jackyun.com/open/openapi/do`，复用现有应用的服务端 AppKey / AppSecret 和 MD5 签名。
- 请求：`pageIndex` 从 0 开始，`pageSize=50`，`includeDeleteAndBlockup=0`。不传编码、名称、修改时间限制。
- 返回：`result.data.warehouseInfo[]`，使用 `warehouseId`、`warehouseCode`、`warehouseName`；删除、停用记录不供新添加选择。
- 读到空数组结束；短页继续查询；重复编码/ID、缺失字段或分页失败时不提供部分列表。最多 100 页。

新用户登录后的空仓库页会自动加载列表，可按名称或编码搜索。选择仓库后点击“添加并初始化采集”，将官方名称和 ID 保存到当前账户，并在同一个数据库事务中加入现有后台采集队列。已有用户的“增加仓库”使用同一组件，过滤已添加编码。重复提交不覆盖已有名称、历史或配置，不重复创建正在排队的任务。

初始化使用现有 worker；它需要正常运行。加入队列不表示库存已采集完成，完整性检查仍沿用现有 SKU/库存核验流程。读取仓库目录不会自动添加或采集全部仓库，也不向吉客云创建仓库。

列表来自服务器上配置的同一个吉客云应用，并非每个钉钉用户的吉客云个人权限。各账户在本站保存的数据仍独立。服务端缓存完整目录 60 秒以合并重复请求；点击“重新获取”和添加时会重新查询官方目录，同时进行的查询复用一个请求，避免使用已停用或删除仓库的旧列表。响应不允许浏览器缓存。密钥不返回浏览器、不记录进日志。

管理员需要为当前应用订阅并授权 `erp.warehouse.get`。列表读取失败时，页面显示错误并允许重试；已有编码的用户仍可选择“手动添加”。不需要用户到吉客云查编码作为正常初始化步骤。

验证：`npm run test:accounts` 包含仓库目录分页、签名、长 ID、删除/停用过滤、异常数据、缓存刷新、账户隔离和入队回滚测试。生产构建后可运行 `node tests/warehouse-discovery-http.mjs`，验证从添加到 worker 完成库存发布的整个初始化流程；设置 `TEST_BROWSER=true` 可同时检查新用户和增加仓库的页面，以及筛选后旧选择失效、刷新后重新选择。测试使用模拟响应，不访问真实吉客云业务数据。

2026-10-19 已使用历史本地 `web-app/.dev.vars` 中的现有应用配置进行只读实测：3 次请求均为 HTTP 200 / code 200，分页返回 50、15、0 行，共 65 个可用仓库，总耗时约 0.54 秒。已确认包含 CK031。结果保存在 `outputs/warehouse-discovery/2026-10-19T02-16-28-096Z/`，只保存仓库编码、名称、ID 与分页验证摘要，不保存密钥或仓库联系资料。

复测命令（在 web-app 目录执行）：`node --env-file=.dev.vars scripts/probe-warehouses.mjs`。该脚本不添加仓库配置、不触发库存采集。当前 Next.js 运行配置读取进程环境变量，生产环境仍需正确设置 `JACKYUN_APP_KEY`、`JACKYUN_APP_SECRET`；历史 `.dev.vars` 不会自动成为生产配置。
