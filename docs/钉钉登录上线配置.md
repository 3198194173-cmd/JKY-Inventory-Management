# 钉钉登录与独立账户：上线配置

本轮已实现代码，默认保持原密码登录。此文不表示已切换生产环境，也不表示钉钉真实应用权限已验证。

## 1. 企业与应用

已按提供的信息预填 CorpID 和指定管理员 unionId 到 `scripts/configure-dingtalk-login.mjs`。登录时会用公司内部应用的通讯录接口把 unionId 映射为 userId，再绑定 `(CorpID, userId)`。第一个普通员工不会成为管理员。

在钉钉企业内部应用配置“钉钉登录与分享”，登记回调地址：

`https://inventory.casebang.tech/api/auth/dingtalk/callback`

应用需开放网页登录、获取个人身份及公司成员信息读取权限，通讯录可见范围须覆盖需要登录的员工。使用 `openid corpid` 授权取得服务端返回的企业 ID，同时核验公司通讯录中的 userId、unionId 和部门归属。`active` 只是激活状态，不被当作在职证明。实际权限名称与发布状态以钉钉开发后台为准，需用本人和其他员工真实登录验证。

参考：[钉钉官方 OAuth 说明](https://opensource.dingtalk.com/developerpedia/docs/develop/permission/token/browser/get_user_app_token_browser/)、[根据 unionId 查询 userId](https://open.dingtalk.com/document/orgapp-server/query-a-user-by-the-union-id)、[用户详情](https://open.dingtalk.com/document/orgapp-server/query-user-details)。

## 2. 准备配置，不启用

在服务器项目目录执行：

```bash
cd /home/ubuntu/apps/JKY-Inventory-Management
node scripts/configure-dingtalk-login.mjs
nano .env.production
```

填写 `DINGTALK_LOGIN_CLIENT_ID` 和 `DINGTALK_LOGIN_CLIENT_SECRET`。这两个是登录应用的 AppKey 和 AppSecret，保留在服务器，不提交 Git。若确认现有机器人就是同一个公司的内部应用，且已具备上述登录与通讯录权限，可执行以下命令复用原凭证，不会输出密钥：

```bash
node scripts/configure-dingtalk-login.mjs --use-robot-app
```

此时 `INVENTORY_DINGTALK_LOGIN_ENABLED=false`。原 `INVENTORY_OWNER_ID` 不得修改；指定管理员绑定后继续使用这个历史 owner，旧仓库和记录不迁移给其他员工。

## 3. 备份与启用

先使用现有 `scripts/backup.mjs` 做包含 WAL 一致性的数据库备份并保存 `.env.production` 的私有备份。生产切换时暂时停止后台 worker，确认新版本构建成功后：

```bash
node scripts/configure-dingtalk-login.mjs --enable
sudo docker compose up -d --force-recreate web worker
```

启用命令会关闭密码登录。新的钉钉登录需要 HTTPS；桌面和手机均通过同一个授权入口。OAuth 事务与浏览器绑定，5分钟失效，只能使用一次，用户令牌不保存在浏览器和日志。

先由指定管理员登录，核对旧仓库和历史数据，然后让另一名本公司员工登录检查空仓库引导，并验证公司外账号被拒绝。真实联调未通过前不要对外开放入口。数据库增量 `0017_company_accounts.sql` 在服务启动时自动执行，不清空历史业务表。

## 4. 使用与边界

- 员工自动开通为空空间，主动添加仓库后才建立自己的配置，自动预警默认关闭。
- 管理员“账户管理”可调整角色、禁用/归档、撤销会话、授予群，并进入指定账户管理数据。页面持续提示正在管理谁，业务写入记录实际操作者与目标账户。
- 同公司真实 ERP 库存可能相同；独立的是平台中的配置、采集时间、快照、入库核验、在途及通知历史。管理员可以查看禁用账号的历史数据，但该账号的任务与通知不会继续执行。
- 普通成员只可选择管理员授权的群；授权不会自动勾选仓库接收群。群消息一旦发送，同群成员仍能看到已有卡片。报告 Excel 下载另行校验登录和归属，不能仅凭下载令牌访问他人数据。
- 服务端每次请求检查账号状态；企业成员归属最多缓存15分钟，过期必须在线核验。后台任务和分段通知同样检查；网络故障不放行。已经发出的外部请求不能撤回，后续请求和通知会停止。
- 禁用账号不会被再次钉钉登录自动启用。必须保留至少一名有效管理员，角色变更、禁用和归档在数据库事务内检查。

## 5. 回退

若钉钉应用权限尚未就绪，执行 `node scripts/configure-dingtalk-login.mjs --disable` 并重新创建 web、worker，可恢复原密码入口，同时暂停钉钉会话入口和非历史管理员账户的后台任务。保留新版本和数据库结构，不能将已升级数据库直接交给旧版本运行；新员工数据不会被删除或改写成管理员数据。需要回退代码时必须停服务并恢复配套的旧数据库一致性备份，期间的新写入需另行保留。

原管理员密码在此前聊天中出现过，正式上线时应在私有服务器终端更换；本轮代码没有改动该密码。
