# 钉钉原生库存预警消息卡片

服务器通过“创建并投放卡片”接口发送真实字段和原生图表数据，不生成或上传报表图片。每张12款，按库存周转升序发送，保留全部预警商品。群内展示商品编码、库存、销量均值、库存周转和近7天净销量图表；每款可展开每日销量明细，图表开启详情查看。

卡片展示本次采集对应的报告数据，不自动变成实时库存。新的采集通过下一份预警报告发送。每日每仓每群去重、手动通知次数及失败不自动重发的规则保持一致。

## 导入原生模板

1. 打开自己已关联“吉客云库存预警”应用的消息卡片编辑页，通过“更多 → 导入卡片模板”导入 [dingtalk-inventory-card.json](./dingtalk-inventory-card.json)。文件已替换为原生版本，不能继续使用旧的图片组件模板。
2. 大纲树应包含标题、摘要、“预警商品列表”循环容器；列表内包含独立指标、原生 Chart 和“每日销量明细”折叠面板。模板没有 Image 组件。
3. 导入后的模拟数据有两款商品，包括负销量，用于检查原生图表和展开明细。正式发送由服务器替换为真实数据，不使用模拟值作为销量。
4. 确认列表绑定 `rows`，图表绑定 `rows[0].chart` 并开启详情，文字绑定对应的 `rows[0]` 字段。折叠面板 ID 按每款独立的安全 stateKey 区分，各款独立展开。原生图表的样式、详情面板和宽屏布局由钉钉客户端决定。
5. 点击保存，由平台编译编辑结构，再发布模板。已有模板 ID 不变；如新建模板，复制新的完整 ID 更新服务器配置。

模板参考钉钉官方的原生 Chart、Loop、CollapsePanel 示例，编辑结构、变量匹配和数据传输已通过本地验证。实际导入、编译及各客户端的交互显示仍需发布后验证，网页预览不是钉钉客户端截图。

## 数据绑定

请求仍调用 `/v1.0/card/instances/createAndDeliver`，`cardData.cardParamMap` 中每个值都是字符串：

- `title`、`summary`、`footer`：原生文字。
- `config`：JSON 字符串，包含 `autoLayout: true`。
- `rows`：JSON 数组字符串，每项包含 `stateKey`、`goodsNo`、`goodsName`、`unitName`、`quantity`、`average`、`turnover`、`salesDetail` 和 `chart`。
- `chart`：原生 `lineChart`，数据为日期 `x`、数值 `y` 和系列 `type`，开启详情显示。它不是 ECharts 配置，也不是图片。

文字字段保留数量的精确十进制字符串。图表使用数值，保留负销量、零销量；缺失日期不补零，不同有效数据段不跨缺日相连。超出 JavaScript 安全数值范围的数量仍在文字明细中精确显示，图表不绘制该点。

网页预览使用同一份商品数据，点击编码展开每日数量与可交互 ECharts 图表。钉钉客户端使用自己的原生图表渲染器，两者布局不保证像素一致。

## 更新云端

先导入、保存和发布原生模板，再更新应用代码。在 `/home/ubuntu/apps/JKY-Inventory-Management/.env.production` 配置：

```dotenv
DINGTALK_CARD_TEMPLATE_ID=当前原生模板的完整ID
```

纯 UUID 自动补齐 `.schema`，已有后缀不重复追加。保留应用凭证。原生版本不发送 `reportImage`；旧图片模板与新发送数据不兼容，须同时更新模板和代码。

```bash
cd /home/ubuntu/apps/JKY-Inventory-Management
git pull --ff-only origin main
# 仅更换模板 ID 时编辑环境文件
nano .env.production
sudo docker compose build web
sudo docker compose up -d --force-recreate web worker
sudo docker compose ps
```

未配置模板 ID 时继续发送文字通知。发布后在网页预览，点击“立即发送预警”，检查新群消息中的数值、负销量、图表详情和折叠面板。之前的图片卡片不会自动改成原生卡片。开发测试只使用模拟接口，不向真实群发送消息。

## 权限及失败排查

机器人所在群列表需要“钉钉群基础信息管理权限”；发送原生卡片需要“互动卡片实例写权限”，并确认模板关联发送凭证对应的应用、应用及模板按平台要求发布。

- 群消息数值为空：核对实际使用的模板 ID 和 `rows` 绑定，确认导入的是最新原生模板。
- `param.templateNotExist`：核对完整模板 ID、模板保存状态、关联应用和发布状态。
- HTTP 403：核对互动卡片实例写权限。
- 群或机器人错误：刷新群列表，确认机器人仍在目标群，凭证与关联应用一致。

页面只显示安全错误码、请求编号和排查提示，不回显可能包含凭证的原始响应。明确拒绝的 400/401/403/404/422 标记发送失败；超时或响应不确定标记未确认，先核对群消息。30秒冷却按发送尝试计算，不代表钉钉已受理。
