# 钉钉原生库存预警消息卡片

服务器通过“创建并投放卡片”接口发送真实字段和原生图表数据，不生成或上传报表图片。每张12款，按库存周转升序发送，保留全部预警商品。群内展示商品编码、库存、销量均值、库存周转和近7天净销量图表；表头只显示一次，每款一行小曲线；点击曲线使用钉钉原生详情查看，不再添加每日销量折叠面板。

卡片展示本次采集对应的报告数据，不自动变成实时库存。新的采集通过下一份预警报告发送。每日每仓每群去重、手动通知次数及失败不自动重发的规则保持一致。

## 导入原生模板

1. 打开自己已关联“吉客云库存预警”应用的消息卡片编辑页，通过“更多 → 导入卡片模板”导入 [dingtalk-inventory-card.json](./dingtalk-inventory-card.json)。文件已替换为原生版本，不能继续使用旧的图片组件模板。
2. 大纲树应包含标题、摘要、“预警商品列表”循环容器；列表内每款只有一行，包含商品编码、独立指标和64高度的原生 Chart。模板没有 Image 或 CollapsePanel 组件。
3. 导入后的模拟数据有两款商品，包括负销量，用于检查原生图表及点击曲线查看详情。正式发送由服务器替换为真实数据，不使用模拟值作为销量。
4. 确认列表绑定 `rows`，图表绑定 `rows[0].chart` 并开启详情。循环中的文字使用 `${loop.goodsNo}`、`${loop.quantity}`、`${loop.average}`、`${loop.turnover}`；这是循环当前项的动态文字语法，不能写 `${rows[0].quantity}`，后者会原样显示成参数。原生图表的样式、详情面板和宽屏布局由钉钉客户端决定。
5. 点击保存，由平台编译编辑结构，再发布模板。已有模板 ID 不变；如新建模板，复制新的完整 ID 更新服务器配置。

视觉样式使用680宽的桌面横向布局、浅蓝表头、正文数值和细分隔线，只有标题与预警周转值突出显示。数据单元格使用正文样式，避免继承标题的粗体样式；编码列加宽并提供完整编码与名称的悬浮说明。标题、表头、数据行和底部使用编译器支持的数字外边距，避免依赖未编译进组件的旧 Grid padding 字段。搭建器中选择桌面端预览，移动端宽度和原生图表细节仍由客户端控制，发布后分别检查。网页预览在手机宽度下允许横向滚动。

模板参考钉钉官方的原生 Chart 和 Loop 示例，编辑结构、变量匹配和数据传输已通过本地验证。实际导入、编译及各客户端的交互显示仍需发布后验证，网页预览不是钉钉客户端截图。

## 数据绑定

请求仍调用 `/v1.0/card/instances/createAndDeliver`，`cardData.cardParamMap` 中每个值都是字符串：

- `title`、`summary`、`footer`：原生文字。
- `config`：JSON 字符串，包含 `autoLayout: true`。
- `rows`：JSON 数组字符串，每项包含 `goodsNo`、`goodsName`、`unitName`、`quantity`、`average`、`turnover` 和 `chart`。
- `chart`：原生 `lineChart`，数据为日期 `x`、数值 `y` 和系列 `type`，开启详情显示。它不是 ECharts 配置，也不是图片。当前客户端使用 `legend: false` 隐藏图例，`xAxisOptions.label: false` 隐藏重复日期标签，`lineShape: "smooth"` 渲染平滑曲线，保留纵轴标签以保留原生详情的数值提示。旧 F2 的 ticks/padding 配置不再使用。64高度为曲线提供更多可绘制空间，销量值不做放大或归一化；详情使用客户端原生图表面板。

文字字段保留数量的精确十进制字符串。图表使用数值，保留负销量、零销量；缺失日期不补零，不同有效数据段不跨缺日相连。库存等文字字段仍保留精确数量。超出 JavaScript 安全数值范围的销量不绘制该点，也不以近似值替代。

网页预览使用同一份商品数据，点击小曲线展开一张带坐标和提示的详细 ECharts 图表，再点小曲线或“收起”关闭；不增加每日销量列表。钉钉客户端使用自己的原生图表渲染器，两者布局不保证像素一致。

## 更新云端

先导入、保存和发布原生模板，再更新应用代码。在 `/home/ubuntu/apps/JKY-Inventory-Management/.env.production` 配置：

```dotenv
DINGTALK_CARD_TEMPLATE_ID=当前原生模板的完整ID
```

纯 UUID 自动补齐 `.schema`，已有后缀不重复追加。保留应用凭证。原生版本不发送 `reportImage`；旧图片模板与新发送数据不兼容，须同时更新模板和代码。

```bash
cd /home/ubuntu/apps/JKY-Inventory-Management
git pull --ff-only origin main
# 仅更换模板 ID 时编辑环境文件
nano .env.production
sudo docker compose build web
sudo docker compose up -d --force-recreate web worker
sudo docker compose ps
```

未配置模板 ID 时继续发送文字通知。发布后在网页预览，点击“立即发送预警”，检查新群消息中的编码、数值、负销量和曲线点击详情。之前的图片卡片不会自动改成原生卡片。开发测试只使用模拟接口，不向真实群发送消息。

## 权限及失败排查

机器人所在群列表需要“钉钉群基础信息管理权限”；发送原生卡片需要“互动卡片实例写权限”，并确认模板关联发送凭证对应的应用、应用及模板按平台要求发布。

- 群消息数值为空：核对实际使用的模板 ID 和 `rows` 绑定，确认导入的是最新原生模板。
- `param.templateNotExist`：核对完整模板 ID、模板保存状态、关联应用和发布状态。
- HTTP 403：核对互动卡片实例写权限。
- 群或机器人错误：刷新群列表，确认机器人仍在目标群，凭证与关联应用一致。

页面只显示安全错误码、请求编号和排查提示，不回显可能包含凭证的原始响应。明确拒绝的 400/401/403/404/422 标记发送失败；超时或响应不确定标记未确认，先核对群消息。30秒冷却按发送尝试计算，不代表钉钉已受理。
