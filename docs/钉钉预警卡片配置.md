# 钉钉库存预警卡片

代码已支持把横向报表图片嵌入钉钉消息卡片。每个货品占一行：商品编码、库存、销量均值、库存周转、近7天销量折线。折线使用 ECharts 的平滑折线。图片支持点击放大；卡片内的曲线是采集时的静态报告，没有网页的悬停提示。

每张12款，按周转由小到大发送，所有预警货品均保留。多张卡片标注张数与总数；每天每仓每群去重的规则仍适用。手动发送不占用自动通知次数。卡片失败或响应不确定时不改发文字、不自动重试，先查看群消息及页面结果。

## 创建并绑定自己的模板

用户确认 `957e3c25-a2d9-4cd3-a424-be40f18a9f9b` 来自“数据报表模板”的案例预览，不是自己的已保存模板；不能继续把这个案例 ID 配置为发送模板。需先创建自己的模板，取得新的 ID。

高级卡片接口使用带 `.schema` 后缀的 schema ID。配置为纯 UUID 时，代码会补齐 `.schema`；已包含后缀时不重复追加。补后缀仅修正格式，不会替你创建模板。

1. 返回卡片平台的模板管理，点击“新建模板”，名称可填“库存预警报告”；卡片类型选择“消息卡片”，场景选择“普通卡片”，关联应用选择“吉客云库存预警”，创建后进入自己的模板编辑页。也可使用案例创建模板，但必须保存到自己的模板管理中。
2. 在“变量”中新增字符串变量 `reportImage`。放置一个“图片”组件，将图片来源绑定到该变量。设置宽度填满、自适应图片高度，并启用图片预览。删除演示数据及演示图表，报告图片本身已包含标题、时间和列表。
3. 可选新增字符串变量 `title`、`summary`、`footer`，用于原生卡片头、摘要和说明；避免重复展示报告图片里的标题。服务端同时传入这些字段。
4. 若模板支持 PC 宽屏自动布局，新增对象变量 `config`，其中 `autoLayout` 为布尔类型。服务端会传入 `{"autoLayout":true}`。PC 端宽度取决于模板和钉钉客户端支持，手机端按屏幕显示，可以点图片放大查看。
5. 保存模板；如平台要求发布后生效，完成模板发布。返回自己的模板列表，复制刚创建模板的新 ID。应用权限管理中开通“互动卡片实例写权限”，按平台要求发布应用。图片使用“上传媒体文件”接口获得钉钉媒体 ID，不需要在公网开放库存图片下载地址。

服务器只传变量数据，无法凭模板 ID 修改搭建器里的组件。模板未绑定 `reportImage` 时，即使 API 受理成功，也无法显示报表图片。

## 云端启用

在 `/home/ubuntu/apps/JKY-Inventory-Management/.env.production` 新增或更新：

```dotenv
DINGTALK_CARD_TEMPLATE_ID=替换为刚创建模板的完整ID
```

保留现有 `DINGTALK_CLIENT_ID`、`DINGTALK_CLIENT_SECRET`、`DINGTALK_ROBOT_CODE`。重建镜像会安装中文字体和图片渲染依赖；修改环境文件后 web 与 worker 都需重建容器。

未设置 `DINGTALK_CARD_TEMPLATE_ID` 时，继续发送文字通知。网页预览仍可查看新报表；设置后页面标记“卡片发送”。

```bash
cd /home/ubuntu/apps/JKY-Inventory-Management
nano .env.production
sudo docker compose build web
sudo docker compose up -d --force-recreate web worker
sudo docker compose ps
```

在网页“库存预警”里勾选群、预览通知，再点击“立即发送预警”验证。开发测试只模拟钉钉接口，不会替你向真实群发送消息。

## 发送失败排查

HTTP 400 不统一解释为权限不足。页面会显示钉钉的错误码、请求编号（接口有返回时）和对应排查提示，不回显包含凭证或请求数据的原始响应。

- `param.templateNotExist`：接口找不到模板。先检查错误提示中的“接口模板 ID”；代码已将纯 UUID 转为带 `.schema` 的 schema ID。若仍报此错误，确认这个 UUID 来自自己的已保存模板；仅打开案例预览不代表模板已经创建，需先以该案例创建自己的模板，关联当前应用、绑定 `reportImage`、保存，再将新模板 ID 填入配置。
- 群或机器人相关错误：刷新群列表、确认机器人仍在目标群，并核对发送凭证对应的应用。
- HTTP 403：核对“互动卡片实例写权限”及关联应用的授权。

钉钉明确拒绝的 400/401/403/404/422 请求标记为“发送失败”；超时或响应不确定仍标记为“未确认”，避免重复消息。30 秒冷却按“发送尝试”计算，失败也会触发，冷却提示不代表钉钉已受理。修正配置后重新预览并发起新请求；旧请求只查询原结果，不重发。
