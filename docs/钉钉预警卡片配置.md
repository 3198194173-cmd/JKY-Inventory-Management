# 钉钉库存预警消息卡片

服务器通过“创建并投放卡片”接口发送真实商品字段。每仓每群仅发送一张卡片，按库存周转升序包含全部预警商品，不再每6款拆分。桌面和手机均使用默认收起的原生 CollapsePanel，点击“查看全部 N 款预警商品（点击展开／收起）”切换列表显示；不再依赖只在部分客户端生效的根卡片自动折叠。

商品编码、库存、均值、周转均是独立的原生文字数据。桌面展开后为五列表格和原生小曲线；手机展开后为完整编码、三项横排指标和全宽小曲线。为绕过当前 iOS 客户端内嵌原生图表空白的问题，手机的小曲线改为真实7天销量生成的轻量 PNG，仅曲线使用图片，整张报表不生成截图。点击手机小曲线或“7天趋势 · 点击查看”在钉钉内打开详细趋势面板，可点击日期或数据点查看真实数值。

卡片展示本次采集对应的报告，不自动变成实时库存。新的采集通过下一份预警报告发送。每日每仓每群去重、手动通知次数及失败不自动重发的规则保持一致。

## 更新应用及模板

1. 先部署应用代码，确保库存网站可从公网通过 HTTPS 访问，图片及详情端点可用。在云端 `.env.production` 配置 `INVENTORY_SITE_URL=https://inventory.casebang.tech`（替换为实际公网域名），保留 `DINGTALK_CLIENT_SECRET` 和现有模板 ID。不能配置 localhost 或 HTTP 地址。
2. 打开自己已关联“吉客云库存预警”应用的消息卡片编辑页，通过“更多 → 导入卡片模板”导入 [dingtalk-inventory-card.json](./dingtalk-inventory-card.json)。
3. 大纲树应包含分别用于桌面、手机的折叠面板，默认内容不可见。展开后桌面出现五列表头和原生 Chart；手机出现指标布局和 Image 小曲线。两个列表均绑定 `rows`，按设备显示其中一种布局。
4. 模拟数据有两款商品。手机模拟小曲线和详情使用本站的静态示例资源；正式发送会替换为本次报告的真实数据链接。
5. 保存并发布模板。已有模板 ID 不变；如新建模板，复制新的完整 ID 更新服务器配置。纯 UUID 自动补齐 `.schema`，已有后缀不重复追加。
6. 发送一条新预警消息验证：桌面默认收起，点击标题展开全部商品，再点收起；手机展开后小曲线可见，点击后可查看每天数值。旧消息不作为新版模板验证对象。

桌面表头与数据行使用一致列宽和边距；商品编码左对齐，指标居中。手机不挤入桌面五列表格。折叠面板通过钉钉客户端的本地状态切换，无需服务器回调。模板不设置根卡片自动折叠。

```bash
cd /home/ubuntu/apps/JKY-Inventory-Management
git pull --ff-only origin main
# 需要调整公网网站地址或模板 ID 时编辑环境文件
nano .env.production
sudo docker compose build web
sudo docker compose up -d --force-recreate web worker
sudo docker compose ps
```

## 数据绑定与曲线访问

请求调用 `/v1.0/card/instances/createAndDeliver`，`cardData.cardParamMap` 中每个值都是字符串：

- `title`、`summary`、`footer`、`detailTitle`：原生文字。
- `config`：JSON 字符串，包含 `autoLayout: true`。
- `rows`：JSON 数组字符串，每项包含 `goodsNo`、`goodsName`、`unitName`、`quantity`、`average`、`turnover`、`chart`、`chartThumbnail` 和 `chartDetailUrl`。
- `chart`：保留桌面原生 `lineChart` 及点击详情数据。
- `chartThumbnail`：手机图片地址，绑定 `rows[0].chartThumbnail`（变量类型为循环）。
- `chartDetailUrl`：钉钉内详情面板链接，绑定 `rows[0].chartDetailUrl`（变量类型为循环）。

循环中文字使用 `${loop.goodsNo}`、`${loop.quantity}`、`${loop.average}`、`${loop.turnover}`。不要写 `${rows[0].quantity}`，后者会原样显示成参数。

`/api/alerts/trend/[token]` 返回小曲线 PNG，添加 `?view=detail` 返回交互式 SVG 详情页。链接只包含7天日期和销量，以应用密钥校验签名，不含商品、库存、账户或凭证字段。有效链接无需登录即可在钉钉内加载；无效签名返回404。链接在应用密钥更换后失效。

文字数量保留精确十进制字符串。曲线保留负销量与零销量；缺失日期不补零，也不跨缺失日期连接。超出 JavaScript 安全数值范围的销量不绘制该点，不用近似值替代。手机小曲线使用平滑折线，详细面板显示坐标和7天数值。

负库存且有效7天销量均值严格大于门槛时，显示带负号的周转天数，网页库存与周转标红并纳入预警；均值不达标、数据不足7天或入库未核验仍不纳入。

## 权限及排查

机器人群列表需要“钉钉群基础信息管理权限”；发送卡片需要“互动卡片实例写权限”。确认模板关联发送凭证对应的应用，应用及模板按平台要求发布。

- 数值为空或显示参数：核对实际模板 ID、循环变量绑定及最新模板是否已发布。
- `param.templateNotExist`：核对完整模板 ID、保存状态、关联应用和发布状态。
- HTTP 403：核对互动卡片实例写权限。
- 手机图片空白：确认新版模板已经发布，公网 HTTPS 域名指向新应用，图片地址可直接返回 `image/png`，没有登录跳转或代理拦截。
- 桌面无法折叠：确认导入的是含 CollapsePanel 的新版模板，并检查新发送的消息。
- 群或机器人错误：刷新群列表，确认机器人仍在目标群，凭证与关联应用一致。

页面只显示安全错误码、请求编号和排查提示，不回显可能含凭证的原始响应。明确拒绝的400/401/403/404/422标记发送失败；超时或响应不确定标记未确认，先核对群消息。30秒冷却按发送尝试计算，不代表钉钉已受理。

模板已通过官方搭建器 DX、Durbo 两种格式的编译检查。本地官方 SDK 验证了桌面、iOS、Android 分支的折叠状态切换，手机图片加载及详情链接点击；这些检查不等于钉钉 iPhone 真机验证，仍需发布后用新消息确认。本地测试不发送真实群消息。

官方参考：[创建并投放卡片](https://open.dingtalk.com/document/orgapp/create-and-deliver-cards)、[原生组件示例及模板导入说明](https://github.com/open-dingtalk/dingtalk-card-examples)。
