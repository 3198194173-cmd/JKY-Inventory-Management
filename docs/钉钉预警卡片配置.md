# 钉钉库存预警消息卡片

服务器使用“创建并投放卡片”接口发送真实商品字段与原生图表数据。每仓每群发送一张卡片，包含全部预警商品，按周转升序排列。桌面与手机均使用默认收起的原生 CollapsePanel，点击列表标题展开全部商品，再点击收起；不依赖根卡片自动折叠。

桌面展开后保留七列表格与小曲线，第一列显示“商品编码 / 名称”，编码下方常驻显示商品名称。手机展开后依次显示编码与右侧蓝色“7天趋势”入口、整行商品名称、库存/销售均值/周转三个指标，下方另列在途数量与建议补货 / 30天。名称使用真实 `goodsName` 字段并换行，不再只靠悬停查看。点击手机趋势入口打开钉钉原生图表详情，从当前卡片实例读取对应行的真实7天销量。

卡片投放和原生趋势详情不依赖网站地址。`INVENTORY_SITE_URL` 为空或 localhost 时仍正常发送，但隐藏“导出 Excel”按钮。若需要从钉钉下载 Excel，请配置为群成员可访问的库存网站完整地址（HTTP 或 HTTPS），并重建 web、worker；网站的同源校验也使用这个地址，请以同一地址登录。

## 按仓库配置

先选择仓库，再打开“预警”。接收群、销售均值门槛、库存周转天数、每日自动开关、发送时间和商品名称排除分别保存。采集时间在独立的“采集设置”入口保存。时间均为北京时间。

修改销售均值或周转门槛时，主表按当前有效输入立即重新标红；保存后刷新仍生效，关闭未保存的设置则恢复保存值。两项均严格比较，负库存保持带符号周转，缺日/未核验数据不参与。名称排除只在最终通知和预警 Excel 汇总时生效，主表仍按规则标红。例如填写“磁吸背盖”，支持换行、逗号或分号分隔多个关键词；任一名称包含即排除，大小写和全半角统一。预览显示符合规则、排除及实际发送的数量。

启动时自动执行 0014 迁移，将原全局规则和已勾选群复制给已有仓库；之后各仓互不影响。新加仓库默认自动通知关闭、销售均值大于3、周转小于30天、08:00采集、08:30发送，接收群需单独勾选。每天每仓每群自动通知一次，同一仓库手动发送仍有30秒冷却。

## 复制与 Excel

桌面和手机的每个商品下方提供一个紧凑的“复制”按钮，绑定钉钉官方 SingleButton 原生复制动作，一次复制“完整商品编码 + 换行 + 完整商品名称”。卡片桌面表头悬停可查看数据来源和计算公式。卡片外层提供“导出 Excel”，折叠商品列表时仍可下载。Excel 包含编码、名称、库存、销售均值、周转天数、在途数量、建议补货 / 30天、7个日期销量及报告说明。

在途使用发送时最新已核验的调拨入库剩余数量；未核验显示“待核验”。补货直接复用网页计算结果：仅（库存+在途）÷未舍入销售均值<30天时，计算（库存+在途）÷销售均值×30，最低0，四舍五入为整数；为0显示“无需补货”，无有效数据为“—”。历史卡片不会随每小时在途检测自动刷新，重新生成报告才会使用新数据。

下载内容固定为该次发送时的商品数据，包含名称排除后的名单；后续采集或改规则不会改写旧报告。下载链接为随机令牌，90天有效，持有卡片链接者可下载，不需要登录网站。链接过期需生成新报告。代码、名称按文本导出，保留前导零并避免名称被解释为公式；超出 Excel 数值精度的数量以文本保存。网页“预警 → 导出预警”可直接导出当前仓库按当前设置筛选的 Excel，无需公开网站地址。

## 更新与导入

1. 更新应用代码并重新创建 web、worker 容器。
2. 在自己的预警模板编辑页，通过“更多 → 导入卡片模板”导入 [dingtalk-inventory-card.json](./dingtalk-inventory-card.json)。
3. 保存并发布。原模板 ID 不变；新建模板时复制新的完整 ID 更新 `DINGTALK_CARD_TEMPLATE_ID`。纯 UUID 会自动补齐 `.schema`。
4. 发送新消息检查桌面、手机折叠、分别点击两个不同商品的“复制”并粘贴确认编码和名称各占一行、“导出 Excel”，以及手机“7天趋势”打开详情。旧消息不作为新版模板验证对象。

```bash
cd /home/ubuntu/apps/JKY-Inventory-Management
git pull --ff-only origin main
sudo docker compose build web
sudo docker compose up -d --force-recreate web worker
sudo docker compose ps
```

本次新增 copyText、transit、replenishment 数据字段，必须同时更新服务器和模板；只更新其中一项会造成新字段缺失或复制内容为空。

## 数据与交互

`cardData.cardParamMap` 中的 `title`、`summary`、`footer`、`detailTitle` 是文字，`rows` 是完整商品数组的 JSON 字符串，`exportUrl` 是可选的下载地址（空值隐藏按钮），`config` 是包含 `autoLayout: true` 的 JSON 字符串。每个商品包含 `goodsNo`、`goodsName`、`unitName`、`quantity`、`average`、`turnover`、`copyText`、`transit`、`replenishment`、`chart`。不再发送 `chartThumbnail` 或 `chartDetailUrl`。

循环文字使用 `${loop.goodsNo}`、`${loop.quantity}` 等当前项语法。桌面 Chart 绑定 `rows[0].chart`（循环类型）。手机原生趋势入口使用模板变量 `nativeTrendDetailLink`，保存官方图表组件生成的 DX 链接表达式和 Durbo 表达式；由客户端加入当前卡片实例、消息 ID 和当前商品行索引，不是固定指向 `rows[0]`。不要把这个模板变量改成普通服务器字段。

文字数量保留精确十进制字符串。图表保留零销量、负销量；缺失日期不补零、不跨缺失日期连接。超出 JavaScript 安全数值范围的销量不绘制，不用近似值替代。

负库存且有效7天销量均值严格大于门槛时，显示带负号的周转天数，网页库存与周转标红并纳入预警。卡片展示本次采集对应的报告，不自动变成实时库存。

手动发送保存设置与后台每15秒自动检查可能重叠。手动请求现在持久化快照与规则：手动任务先开始时，自动检查按同群、同仓、同快照、同规则跳过已经在途、受理或未确认的报告；自动任务先开始时，30秒内的相同手动请求显示跳过说明，不再次投放。手动记录不占自动每日名额，新快照可继续触发自动通知。明确失败的手动请求不阻挡自动任务；同一请求重放始终只查询结果，30秒冷却结束后可主动发起新的手动请求。

## 排查与验证

发送卡片需要“互动卡片实例写权限”，模板须关联当前发送应用并保存、发布。

- `param.templateNotExist`：核对完整模板 ID、保存状态、关联应用和发布状态。
- 数值空白或显示参数：核对 `rows` 与循环文字绑定。
- 手机仍显示空白图形区域：确认导入并发布本版模板，检查新消息。
- 获取访问令牌失败：卡片投放尚未调用，检查应用凭证及服务器网络。
- 投放超时、网络异常或响应格式异常：保留未确认并显示原因，先核对群消息，不自动重发。
- 桌面无法折叠：确认新版模板包含原生 CollapsePanel。

测试只使用模拟投放接口，不发送真实群消息。已检查官方 DX、Durbo 编译、PC/iOS/Android 布局与折叠交互、手机不同商品的原生详情链接，以及 localhost 配置下的单卡投放。本地 SDK 的复制检查仅拦截原生动作并核对当前商品的文字参数，没有写入真实钉钉客户端的剪贴板。本地 SDK 不代替钉钉桌面或 iPhone 真机验证，发布后需用新消息确认。
