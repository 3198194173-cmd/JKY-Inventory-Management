# 钉钉机器人云端接入

适用于当前企业内部应用机器人。云端 worker 自动查询机器人所在群，网页展示群列表，由用户勾选接收预警的群。群发现和主动发送使用钉钉 HTTP 接口，无需手填群 ID、在群里发送口令，也不依赖持续运行 Stream。Stream 工具仍可用于截图中的控制台连接验证。

## 1. 云端填写应用凭证

拉取新版代码并构建 web 镜像后，在服务器执行：

```bash
cd /home/ubuntu/apps/JKY-Inventory-Management
nano .env.production
```

填写同一个钉钉应用的配置（替换下列说明文字；不要发到聊天或提交 Git）：

```dotenv
DINGTALK_CLIENT_ID=凭证与基础信息里的ClientID
DINGTALK_CLIENT_SECRET=同一应用的ClientSecret
DINGTALK_ROBOT_CODE=机器人页面里的RobotCode
```

RobotCode 尚未生成时可先留空，不影响事件连接验证。只需以上三项凭证；旧的 `DINGTALK_OPEN_CONVERSATION_ID` 不再作为通知目标。新同步的群默认不勾选，填写凭证不会自行开启通知。

## 2. 验证截图中的事件 Stream 通道（需要时）

当前库存预警不需要订阅通讯录、审批等业务事件。验证之前不要勾选这些业务事件，也不要在已有业务事件消费者的应用上运行这个临时工具。

```bash
sudo docker compose run --rm --no-deps web node scripts/dingtalk-stream.mjs --verify-events
```

看到“事件 Stream 已建立 WebSocket 连接”后，保持终端运行，在钉钉开发者后台当前应用的 **事件订阅** 页面依次操作：

1. 推送方式选择“Stream模式推送”。
2. 点击“已完成接入，验证连接通道”。
3. 控制台提示成功后点击“保存”。

WebSocket 连接建立不等于控制台验证已经通过，以控制台结果为准。工具最多保持 5 分钟，完成后 `Ctrl+C` 结束。失败或超时可重新运行。它仅用于通道验证；若意外收到业务事件，返回 `LATER`，不会把未处理的事件标成消费成功。不提供业务事件处理或自动重连。机器人配置与事件订阅是两个入口，仅主动群预警不要求开启额外业务事件。

## 3. 发布机器人与应用

1. 点击左侧 **机器人**，启用机器人、填写名称和描述，消息接收模式选择 **Stream**，保存/发布机器人配置。
2. 在 **权限管理** 申请“获取机器人所在群信息”和“机器人发送群消息”对应接口权限；如需显示群名，再申请“查询群简要信息”。以控制台当前接口权限说明及企业可授权范围为准，授权后发布新版本。
3. 点击左侧 **版本管理与发布**，创建版本、填写更新说明，设置可见范围包含你和目标群使用人员，然后按企业流程发布/由管理员批准。顶部提示“版本发布后，当前修改才能生效”指向的就是这一处。
4. 在同一企业的目标内部群的机器人管理中添加该机器人。若搜不到，检查应用发布状态、可见范围和群类型。

发布不需要先填写群 ID。事件验证模式也不需要群 ID，因此没有“必须加群才能发布、必须发布才能获取群 ID”的循环。

## 4. 自动同步群列表

现有 worker 启动时同步一次，之后每15分钟同步。网页“预警” → “刷新群列表”可立即查询；连续刷新至少间隔10秒。后台同步与库存采集独立，库存页面读取本地缓存，不在刷新库存或排序时请求钉钉。

使用 `POST /v1.0/robot/installed/groups/query`，传入 RobotCode，按 `maxResult=10`、`nextToken` 完整分页取得 `openConversationIds`。只有全部分页成功才更新群成员关系；权限错误、超时、无效响应和分页失败保留原列表并展示错误。

群名通过 `POST /v1.0/im/sceneGroups/query` 按群 ID 查询并缓存一天，每轮最多20个。普通群、权限或场景限制可能无法读取群名，此时网页展示“群名称暂未获取”和完整群 ID；自动发现及勾选仍然可用。

仍在群中的机器人保留原勾选；移出群后清除该群勾选并停止发送。重新加入需重新勾选。更换应用或 RobotCode 后展示对应机器人的列表。默认 Stream 获取口令模式保留为辅助诊断，不再是启用群通知的步骤。

## 5. 加载发送配置，启用预警

在没有采集运行时执行：

```bash
sudo docker compose up -d --force-recreate web worker
sudo docker compose ps
curl --fail http://127.0.0.1:3108/api/health
```

打开库存页面的“预警” → “刷新群列表” → 勾选一个或多个接收群 → 查看预览、确认门槛 → 开启群通知 → 保存设置。保存不发送消息；之后完整采集结束时，符合规则的货品汇总为简洁通知，每用户、应用、机器人、仓库、群、北京时间日期最多尝试发送一次。某群发送失败不影响其他勾选群，发送未确认当天不自动重试。仅已勾选且机器人仍在群中的目标可发送；Stream 工具退出不影响主动通知。

旧版按仓库保存的当天发送记录仍被保留，当天已有旧版发送尝试时不重复发送。未在网页选群的旧部署需重新选择群后才能继续通知。

## 排查

- HTTP 401/403：检查凭证是否来自当前应用、是否复制完整、是否已授权，不输出 Secret。
- WebSocket 连接失败：检查服务器到 `api.dingtalk.com` 及返回的 WSS 地址的出站连接和 TLS。不要为此修改其他项目的 Nginx、证书或 DNS。
- 控制台验证失败：确认运行的是 `--verify-events`，凭证对应截图中的应用，工具仍在运行；默认获取群 ID 模式仅订阅机器人 CALLBACK，不能代替 EVENT 通道验证。
- 无群回调：检查机器人已发布并加入同企业内部群，确实 @了机器人，口令与本次运行相同，没有其他接收程序分走回调。
- 群列表为空：先确认机器人已发布且已加入同企业目标群，三项凭证正确，所在群查询接口权限已授权并发布。Stream 在线不代表机器人已发布或该权限生效。
- 群同步失败：网页显示同步错误；先核对接口权限和发布状态，不会因为失败清空原勾选。
- 消息未发送：检查三项配置已加载、群已勾选并保存、预警开关、当前仓库规则、采集是否完整、当天是否已尝试发送；受理成功也需到群核对实际收到。
