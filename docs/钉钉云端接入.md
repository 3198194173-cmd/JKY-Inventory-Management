# 钉钉机器人云端接入

适用于当前企业内部应用机器人。库存 web/worker 的主动群预警使用 HTTP 接口发送；Stream 用于控制台连接验证和接收群内 @机器人 回调以获取群 ID。两者独立，获取群 ID 后无需长期运行本工具。Stream 从服务器向钉钉建立出站 HTTPS/WSS 连接，不需要公网回调地址或开放新的入站端口。

## 1. 云端填写应用凭证

拉取新版代码并构建 web 镜像后，在服务器执行：

```bash
cd /home/ubuntu/apps/JKY-Inventory-Management
nano .env.production
```

填写同一个钉钉应用的配置（替换下列说明文字；不要发到聊天或提交 Git）：

```dotenv
DINGTALK_CLIENT_ID=凭证与基础信息里的ClientID
DINGTALK_CLIENT_SECRET=同一应用的ClientSecret
DINGTALK_ROBOT_CODE=机器人页面里的RobotCode
DINGTALK_OPEN_CONVERSATION_ID=
```

RobotCode 尚未生成时可先留空，不影响事件连接验证。群 ID 不影响连接和应用发布，先留空。`docker compose run` 每次从 `.env.production` 读取最新配置；填写这些字段不会自行开启预警发送。

## 2. 验证截图中的事件 Stream 通道（需要时）

当前库存预警不需要订阅通讯录、审批等业务事件。验证之前不要勾选这些业务事件，也不要在已有业务事件消费者的应用上运行这个临时工具。

```bash
sudo docker compose run --rm --no-deps web node scripts/dingtalk-stream.mjs --verify-events
```

看到“事件 Stream 已建立 WebSocket 连接”后，保持终端运行，在钉钉开发者后台当前应用的 **事件订阅** 页面依次操作：

1. 推送方式选择“Stream模式推送”。
2. 点击“已完成接入，验证连接通道”。
3. 控制台提示成功后点击“保存”。

WebSocket 连接建立不等于控制台验证已经通过，以控制台结果为准。工具最多保持 5 分钟，完成后 `Ctrl+C` 结束。失败或超时可重新运行。它仅用于通道验证；若意外收到业务事件，返回 `LATER`，不会把未处理的事件标成消费成功。不提供业务事件处理或自动重连。机器人配置与事件订阅是两个入口，仅主动群预警不要求开启额外业务事件。

## 3. 发布机器人与应用

1. 点击左侧 **机器人**，启用机器人、填写名称和描述，消息接收模式选择 **Stream**，保存/发布机器人配置。
2. 在 **权限管理** 申请主动发送机器人群消息所需的权限（以当前发送接口文档和控制台为准）。
3. 点击左侧 **版本管理与发布**，创建版本、填写更新说明，设置可见范围包含你和目标群使用人员，然后按企业流程发布/由管理员批准。顶部提示“版本发布后，当前修改才能生效”指向的就是这一处。
4. 在同一企业的目标内部群的机器人管理中添加该机器人。若搜不到，检查应用发布状态、可见范围和群类型。

发布不需要先填写群 ID。事件验证模式也不需要群 ID，因此没有“必须加群才能发布、必须发布才能获取群 ID”的循环。

## 4. 云端获取目标群 ID

确认 `.env.production` 的 RobotCode 已填写。在云端运行（不要同时启动本地或其他机器人接收程序，以免回调被分配到另一连接）：

```bash
sudo docker compose run --rm --no-deps web node scripts/dingtalk-stream.mjs
```

连接后会显示一次性随机口令。在目标群 **@机器人**，发送终端显示的完整口令。工具只接受同一 RobotCode、群聊、正确口令的回调，输出目标群名和 `conversationId` 后退出，不主动向群发消息。

核对群名正确后，将 `conversationId` 的值填入 `.env.production` 中的 `DINGTALK_OPEN_CONVERSATION_ID`。终端输出使用 JSON 双引号转义；引号本身不属于 ID。获取超时或断开时重新运行并使用新口令。`Ctrl+C` 可取消。

## 5. 加载发送配置，启用预警

在没有采集运行时执行：

```bash
sudo docker compose up -d --force-recreate web worker
sudo docker compose ps
curl --fail http://127.0.0.1:3108/api/health
```

打开库存页面的“预警”，先查看消息预览、确认仓库和销量均值门槛，再开启群通知。之后完整采集结束时，符合规则的货品汇总为简洁通知，每用户、仓库、北京时间日期最多尝试发送一次。Stream 工具退出后不影响主动发送；采集进程、DingTalk 发送权限、目标群机器人仍需正常。

## 排查

- HTTP 401/403：检查凭证是否来自当前应用、是否复制完整、是否已授权，不输出 Secret。
- WebSocket 连接失败：检查服务器到 `api.dingtalk.com` 及返回的 WSS 地址的出站连接和 TLS。不要为此修改其他项目的 Nginx、证书或 DNS。
- 控制台验证失败：确认运行的是 `--verify-events`，凭证对应截图中的应用，工具仍在运行；默认获取群 ID 模式仅订阅机器人 CALLBACK，不能代替 EVENT 通道验证。
- 无群回调：检查机器人已发布并加入同企业内部群，确实 @了机器人，口令与本次运行相同，没有其他接收程序分走回调。
- 消息未发送：检查四项配置已加载、预警开关、当前仓库规则、采集是否完整、当天是否已尝试发送；受理成功也需到群核对实际收到。
