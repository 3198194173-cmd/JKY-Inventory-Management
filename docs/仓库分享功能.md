# 管理员仓库分享

管理员在账户管理中选择“仓库分享”，输入同事手机号，通过本企业钉钉通讯录确认姓名和 userId，再选择自己的仓库复制。支持从已开通的公司账户中选择接收人。

- 未登录同事在确认复制时才创建账户，状态显示“待首次登录”；首次真实钉钉登录按 CorpID + userId 匹配，unionId 必须一致，沿用原账户和数据空间。
- 一次性复制仓库配置、所有已完成库存快照、每日快照索引、销售与入库核验、在途历史和完成标记，以及已结束采集记录。时间、数量精度和缺失状态保持原样。新快照采用独立 ID，之后各账户独立采集和修改。
- 目标已有同编码仓库时跳过，不覆盖或合并。不能复制给自己，也不能绕过禁用、归档或企业身份校验。
- 复制预警阈值、排除词及时间，自动预警关闭；群授权、接收群、发送记录、报告下载令牌、会话和运行中任务不复制。待首次登录账户不执行后台采集。
- 原始手机号只用于服务端查询，不写入数据库、URL、审计或日志；短期身份凭证绑定管理员，确认复制前再次核验企业成员身份。手机号查询限频。
- 创建账户、复制多仓库和保存结果在同一事务内完成，失败整体回滚。请求 ID 防止重复提交；审计记录操作者、接收人、复制/跳过仓库和数据数量。

钉钉应用需额外开通“根据手机号姓名获取成员信息的接口访问权限”（`qyapi_get_member_by_mobile`），同时保留成员信息读权限及对应员工的通讯录范围，发布新版本后生效。使用 `topapi/v2/user/getbymobile` 获取 userId，再用 `topapi/v2/user/get` 核验 unionId 和企业部门归属。手机号查不到时不得按姓名猜测或创建账户。

本功能不主动向同事发送消息。真实企业通讯录联调与生产部署需在本地实现完成后执行。

## 本地验证（2026-10-15）

生产构建和58项库存、在途、预警及账户测试通过，其中新增9项分享测试覆盖数据精度、快照重映射、首次登录复用、同码跳过、幂等、失败回滚、身份串号、禁用与凭证过期。实际 HTTP 检查覆盖管理员权限、同源校验、管理其他空间时仍只分享操作者自己的仓库。桌面与390像素手机窗口检查通过，无横向溢出或脚本错误。

手机号接口使用隔离的模拟企业数据验证；没有查询真实同事，也没有改动云端服务器。实际企业权限是否就绪，仍需发布应用后联调确认。
