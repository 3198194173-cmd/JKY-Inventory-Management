# 星空连接与20行探测

更新：2026-10-22。网页后端已接入，真实账号、服务器网络和同条件报表对账需要部署后由用户测试。本轮只读登录与首页最多20行，不执行全量采集，不写入ERP。

## 操作顺序

1. 钉钉登录，进入金蝶工作台 → 准备数据 → 公司销量或公司库存 → 连接与20行探测。
2. 服务地址固定为 `https://benks.ik3cloud.com/k3cloud/`。填写该服务的实际账套ID、用户名及密码，点击测试连接。密码发送到本应用专用后端，再用于该固定金蝶地址登录；不发送到其他主机，不跟随重定向。
3. 登录通过只表示取得会话，不表示拥有全部报表权限。连接按操作者及当前目标账户绑定，有效期15分钟；关闭配置窗口、切换账户、重新登录测试或重启服务后旧连接不能继续使用。密码在登录请求结束时从页面清空，服务器不会把密码留在会话中或数据库中；不得在聊天、日志或Git中粘贴密码。
4. 公司销量：选择开始和截止日期，填写销售、结算组织的准确编码或名称。编码103是旧实测组织。后端实时查询组织内码，若无权限、无结果或重名会停止，不把编码直接当内码。销售条件沿用已验证的全部单据状态、全部统计套件、包含赠品及服务物料等参数。
5. 公司库存：填写真实的非默认方案内码FSCHEMEID。预填 `6ad1c8d85e3e71` 是2026-10-16实测“API物料收发汇总”的内码，不保证其他用户可见或日期仍适用。先在星空保存正确的组织、日期、仓库、单据状态等条件。网页的预期库存日期仅供人工核对，不作为接口条件发送；后端不猜测QuicklyCondition字段或以方案名称冒充内码。
6. 点击对应的20行探测。页面显示接口原始总数、样本行数、返回列、实际请求、组织及样本标注。库存显示是否取得CurQueryId，不向前端输出其实际会话值。销售的RowCount可能含报表显示行，不能直接当作去掉小计后的业务行数。
7. 下载样本JSON，与金蝶同条件页面或Excel按物料、客户/仓库、单位等维度核对，不只比较行号。完整请求和警告随记录保留；销售客户排除名单及命中样本仅标注，不删行、不汇总整表、不根据赠品标记丢弃数量。小数、长内码、空值、0、负数保留原值。

0行是本次请求的实际返回，并不证明业务无数据或所有权限均通过。没有Rows/data数组、列数异常、超过20行、业务失败、组织不匹配等均明确报错，不转为空结果。

## 数据与运行边界

- `POST /api/kingdee/xingkong/connection`：建立内存连接；`DELETE`：关闭连接。Cookie和金蝶会话标识不返回浏览器、不写入数据库。
- `POST /api/kingdee/xingkong/probes`：一次只查询首页20行；`GET`：当前账户最近10次记录。
- `GET /api/kingdee/xingkong/probes/{id}`：按账户校验后查看样本；`?download=1`下载JSON。
- 登录及探测均校验站点同源和本系统登录身份。会话还绑定操作者和目标账户，不能把另一账户的连接拿来查询。
- 样本存入金蝶库的独立`kd_probes`表，带`sampleOnly=true`、`apiReadComplete=false`、`uiEquivalentVerified=false`。不会进入`kd_batches`或五项来源就绪统计，不覆盖已生成明细，不修改吉客云库存业务表。
- 登录每操作者/目标账户一分钟最多5次，无自动密码重试；每连接同时只允许一个探测。登录超时25秒，组织查询每次25秒，报表请求120秒。现有库存Nginx的300秒代理超时可覆盖一次销售探测最多两次组织查询加报表请求。
- 当前单实例网页进程保管连接，重启会丢失会话。将来多副本部署需要连接粘性或专门的采集服务，不能直接横向复制后宣称会话可共享。

## 本地验证与部署

```powershell
npm run test:xingkong
npm run test:kingdee
npm run build
node tests/xingkong-http.mjs
node tests/kingdee-http.mjs
```

星空新增9组离线测试及HTTP集成测试，使用隔离数据库和模拟ERP响应，测试不会访问真实金蝶。模拟仅由测试进程预加载，生产没有模拟接口开关或可填写的任意服务地址。通过这些测试不能宣布真实账套登录或云端报表已经核验。

代码提交、推送后，在服务器现有项目目录拉取并构建：

```bash
git pull --ff-only origin main
sudo docker compose build web
sudo docker compose up -d --no-build web worker
sudo docker compose ps
curl -fsS http://127.0.0.1:3108/api/health
```

沿用原`.env.production`、钉钉登录和storage挂载，无需把金蝶密码写入环境变量。升级前按原流程备份并避开正在运行的采集任务；不要删除数据卷。构建成功后才更新容器。现有备份脚本只备份吉客云数据库，金蝶库及原件目录需另外纳入备份。
